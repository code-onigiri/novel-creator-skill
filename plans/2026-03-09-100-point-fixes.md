## Fix 1 (P0): Humanizer Key Mismatch

**File:** `scripts/novel_flow_executor.py` ~line 1029

**Problem:** `p_payload.get("humanize_prompt", "")` always returns an empty string, but `text_humanizer.py` actually uses the key `"prompt"` for output. This causes the humanizer auto-correction loop to never execute.

**Fix:** Change `"humanize_prompt"` to `"prompt"` (1 line)

---

## Fix 2 (P0): BEAT_SHEET_STUB Not Recognized as Draft

**File:** `scripts/novel_flow_executor.py` ~line 56 + ~line 485

**Problem:** The Beat Sheet template mode writes `<!-- BEAT_SHEET_STUB -->`, but `chapter_is_draft_stub()` only detects `<!-- NOVEL_FLOW_STUB -->`, causing files containing only prompts to enter the gate check and be treated as completed chapters.

**Fix:**
1. Add `BEAT_SHEET_STUB_MARKER = "<!-- BEAT_SHEET_STUB -->"` to the constants section
2. Add detection of this marker in `chapter_is_draft_stub()`
3. Use the constant at stub write sites (consistency)

---

## Fix 3 (P1): one-click Does Not Initialize Graph/Anchor Files

**File:** `scripts/novel_flow_executor.py` `cmd_one_click` function

**Problem:** When creating a new project, `story_graph.json` and `outline_anchors.json` are not created, causing all knowledge graph/outline anchor features to be silently skipped for the first several chapters.

**Fix:** Before `cmd_one_click` returns, use `save_json` to create initial files with minimal structure (`if not exists`).

---

## Fix 4 (P1): RAG Retrieval Results Not Injected into writing_query

**File:** `scripts/novel_flow_executor.py` `continue_write` function ~line 1330

**Problem:** `q_payload` (the top-k historical fragments retrieved by RAG) never enters `writing_query`, making RAG equivalent to "ran but not used."

**Fix:**
1. Move `injected_lines` initialization outside the `enable_constraints` block
2. Extract paragraph text from `q_payload["result"]["retrieved"]` and build a `[Related Historical Plot]` section
3. Restructure `writing_query` concatenation: `query + [Historical Plot] + [Writing Constraints]`

---

## Fix 5 (P1): Knowledge Graph Schema Inconsistency

**File:** `scripts/story_graph_builder.py` `cmd_context` function

**Problem:** `story_graph_updater` writes foreshadowing fields as `planted_chapter` and event fields include `participants` (a list of names), but `cmd_context` only reads `chapter_planted`, `description`. This causes the context to become unusable after graph writeback.

**Fix:** Use dual-compatible reads for all fields in `cmd_context` (`planted_chapter` OR `chapter_planted`, `description` OR `name` OR `hint`, event participants displayed correctly)

---

## Fix 6 (P2): style_anchor.md Format Mismatch with Writing Engine

**File:** `scripts/style_fingerprint.py` + `scripts/novel_chapter_writer.py`

**Problem:** `style_anchor.md` is missing the `perspective/syntax/dialogue` (perspective/syntax/dialogue) three fields that `novel_chapter_writer.py` depends on.

**Fix:**
1. `style_fingerprint.update_project_files` receives a `metrics` parameter and writes `perspective/syntax/dialogue` to `style_anchor.md`
2. `novel_chapter_writer.py` extends its regex to be compatible with both old and new formats
